01 Problem

Anyone screening candidates — recruiters, hiring managers, small-business owners — receives CVs as a pile of mismatched files: PDFs, Word documents, plain text, every one formatted differently. Comparing candidates means opening each file, hunting for the same five or six details, and retyping them into a spreadsheet by hand.

For a batch of 10 CVs that's roughly 30–45 minutes of pure copy-paste, it's error-prone (a mistyped phone number means a lost candidate), and it has to be redone for every new vacancy. Existing Applicant Tracking Systems solve this but are heavyweight, subscription-priced, and require uploading candidates' personal data to a third party — overkill for someone who just needs a comparison table.

“I put 10 CVs in and I tell it: I want name and last name, phone number, email, nationality, years of experience — and it organizes all candidates in a file with the columns I've asked for.” — the founding user request, verbatim

02 Goals & non-goals

Goals

  • One minute, not one hour: from a folder of CVs to an exportable candidate table in under a minute.
  • User-defined columns: the user chooses the fields — in plain language, in their own words and order.
  • Private by default: CVs contain personal data; processing must happen entirely in the user's browser with no server upload.
  • Zero setup: a URL, not an install. No account, no subscription, no configuration.
  • Standard outputs: export to .csv and .xlsx that open cleanly in Excel and Google Sheets.

Non-goals (v1)

  • Candidate ranking, scoring, or matching against a job description.
  • OCR of scanned/image-only PDFs.
  • Storage: no database, no saved sessions, no candidate profiles.
  • Bulk sourcing integrations (LinkedIn, job boards, email inboxes).

03 Users & user stories

PersonaStory
In-house recruiter “I have 30 applications for one role. I want a table of name, contact, nationality and experience so I can shortlist in one sitting.”
Small-business owner “I don't have an ATS. I want to compare the five candidates who emailed me without retyping anything.”
Agency sourcer “Clients ask for candidate summaries in Excel with their columns. I want to define custom columns per client — even unusual ones like notice period.”

04 User flow

① ADD CVs drag & drop / browse → PDF · DOCX · TXT each file parsed to text in-browser, status shown per file ② CHOOSE COLUMNS tap preset chips · or type a sentence: "name, phone number, email, nationality, years of experience" → parsed into ordered columns ③ EXTRACT built-in parser (default) · AI mode (optional) one row per CV, per-file progress line ④ REVIEW + EXPORT click any cell to edit → Export .csv / .xlsx

06 Non-functional requirements

  • Privacy: no CV content leaves the browser in default mode. AI mode sends CV text only to the AI provider's API, only with the user's own key, and this is disclosed in the UI.
  • Performance: a batch of 10 typical CVs parses and extracts in under 10 seconds on a mid-range laptop.
  • Offline-capable: all parsing libraries are vendored — no CDN dependency for core function.
  • Accessibility: keyboard-operable dropzone, live status regions, visible focus states, reduced-motion support.
  • Responsive: usable from 375 px mobile up to desktop; wide tables scroll within their own container.
  • Zero infrastructure: fully static site; deployable to any static host, no backend to operate or secure.

Key design decisions

  • Client-side first, AI as an opt-in tier. Most extraction needs are covered by deterministic rules at zero cost and maximum privacy; the AI tier exists for the long tail of custom columns, and the user brings their own key so the product has no per-use cost to operate.
  • Years of experience is computed, not just matched. When a CV doesn't state “X years of experience”, the engine derives it from the earliest-to-latest employment date ranges and marks it as an estimate (~9).
  • Columns mirror the user's words. Column headers are exactly what the user typed, in the order they typed them — the export looks like the table they asked for, not the schema the tool prefers.

08 Success metrics

  • Time-to-table: < 60 seconds from first file drop to export, for a 10-CV batch (v1 measured: ~15 s with the built-in engine).
  • Extraction accuracy: ≥ 90% of standard fields (name, email, phone, nationality) correct on text-based CVs without manual editing.
  • Completion rate: share of sessions that reach an export after adding files.
  • Zero privacy incidents: no CV content transmitted in default mode — verifiable from the network tab.

09 Risks & mitigations

Users click Extract before files finish parsingExtract button stays disabled until every file is read (FR-10, found in testing)
